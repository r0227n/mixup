# MIXライター

セッション内のMIX情報を、既存の `mixs/` バンドルと同じ形式で記録する。入力されていないコールや検証情報を推測しない。

## 必須の依存スキルとテンプレート

1. 作業開始時に必ず `$okf-creator` を呼び出し、[OKFクリエイター](../okf-creator/SKILL.md)の指示に従う。
2. 作成前に必ず [assets/_TEMPLATE.md](assets/_TEMPLATE.md) を全文読み、出力文書の構造とフィールドを一致させる。
3. `$okf-creator` またはテンプレートを利用できない場合は、MIXファイルを変更せずに不足を報告する。

このスキル固有の規則とOKF仕様が衝突する場合はOKF仕様を優先し、必要なテンプレート修正をユーザーへ報告する。

## 入力を確定する

1. 現在のセッション全体から、対象MIXごとに次の値を抽出する。
   - MIX名
   - 小節数（正の整数）
   - 順序と改行を保持したコール本文
2. 最新のユーザー指示を優先する。同じMIXに関する古い入力と新しい入力が競合する場合は、新しい入力を採用する。
3. MIX名、小節数、コール本文のいずれかを安全に特定できない場合は、ファイルを作らず不足項目だけを確認する。
4. 拍手記号、伏せ字、読み仮名、全角記号、繰り返し表現、始動注記を意味のある内容として保持する。明示的な依頼なしに表記を正規化しない。
5. セッション、添付ファイル、一時ファイルを `resource` や `sources` として記録しない。永続的な出典をユーザーが明示した場合だけ、`$okf-creator` の規則に従って追加する。

## 保存先とファイル名を決める

1. リポジトリルートの `mixs/index.md` と、対象小節の `mixs/<小節>/index.md` を読む。
2. 同じ小節の既存文書について、`title` とファイル名を検索して重複を確認する。
3. 保存先を `mixs/<小節>/` とする。ディレクトリ名には10進数の小節数だけを使う。
4. ファイル名を `<小節>_<slug>.md` とする。
5. `slug` を次の規則で作る。
   - 小文字ASCII英数字とハイフンだけを使う。
   - 日本語は読みをアルファベット表記へ変換する。
   - 単語境界をハイフンで結び、連続するハイフンを1つにする。
   - 汎用的な末尾の `mix` または `MIX` は省く。
   - 固有語は既存ファイルの綴りを優先する。例: `ミョーホントゥスケ広場` → `myohontusuke-hiroba`。
6. 同じ保存先が存在する場合は、タイトルと内容を比較する。
   - 明示的な更新依頼なら既存文書を更新し、未知のフロントマターキーを保持する。
   - 内容が同一なら変更しない。
   - 別MIXとの衝突または意図が不明な変更なら、上書きせずユーザーへ確認する。

## MIX文書を作成する

1. `assets/_TEMPLATE.md` を複製し、すべてのプレースホルダーを確定値で置換する。
2. `{{TITLE}}` をYAML文字列として安全にエスケープする。
3. `{{BARS}}` を引用符なしの正の整数へ置換する。
4. `{{CHANT}}` をコードフェンス内へ挿入し、入力の行順と改行を保持する。
5. セッション入力だけで作成した文書は `status: stable` のままにする。根拠なく `generated`、`verified`、`sources`、`resource` を追加しない。
6. 未置換の `{{...}}` を残さない。

## インデックスを更新する

1. 対象の `mixs/<小節>/index.md` に次の形式で1行追加または既存行を更新する。

   ```markdown
   - [<MIX名>](ファイル名) - <小節>小節のMIX。
   ```

2. 新しい小節ディレクトリを作る場合は、フロントマターなしの `index.md` を次の形で作る。

   ```markdown
   # <小節>小節のMIX

   - [<MIX名>](ファイル名) - <小節>小節のMIX。
   ```

3. ルートの `mixs/index.md` に対象小節へのリンクがなければ追加し、小節数の昇順に並べる。
4. ルート一覧の件数を、対象ディレクトリに存在するコンセプト文書数と一致させる。
5. 既存の一覧順、説明、未知の内容を不必要に書き換えない。

## 検証する

作成または更新後に `$okf-creator` の検証を実行し、さらに次を確認する。

1. パスが `mixs/<小節>/<小節>_<slug>.md` に一致する。
2. ファイル名の小節数、親ディレクトリ、`bars`、`tags`、`description` が一致する。
3. YAMLを実際のパーサーで解析でき、`type` が `Idol Live MIX` である。
4. 対象サブディレクトリの `index.md` が文書へリンクしている。
5. ルート `index.md` のディレクトリリンクと件数が実体に一致する。
6. 未置換プレースホルダー、一時ファイルへの参照、根拠のない来歴・検証メタデータがない。
7. 既存の無関係なMIX文書が変更されていない。

## フォーマットする

すべての作成・更新・検証が終わったら、作業完了前にリポジトリルートで必ず次を実行する。

```bash
mise run format:dprint
```

フォーマットによる変更後に対象文書とインデックスを再検証する。コマンドを実行できない場合や失敗した場合は、理由と未確認のリスクを報告する。

## 結果を報告する

次を簡潔に報告する。

- 作成または更新したコンセプトIDとファイルパス
- 更新したインデックス
- 採用したMIX名、小節数、slug
- OKF検証結果
- `mise run format:dprint` の実行結果
- 解決できなかった入力または表記上の判断
